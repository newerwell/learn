# 项目 1 · 接口设计

> 用法：先定"统一约定"，再列接口总表，最后逐个补细节。
> 判定标准：前端照着这份文档能写出页面，不用回来问后端；阶段 3 你照着它实现后端。

## 一、统一约定

| 项 | 约定 |
|---|---|
| Base URL | `/api/v1`（版本号从第一天就带，改起来不痛） |
| 鉴权 | `Authorization: Bearer <access_token>`；登录/注册接口除外 |
| 时间格式 | ISO 8601 UTC，如 `2026-11-15T08:00:00Z` |
| 分页参数 | `?page=1&pageSize=20`（page 从 1 开始） |
| 分页响应 | `{ "items": [...], "total": 42, "page": 1, "pageSize": 20 }` |
| 错误格式 | `{ "code": "TASK_NOT_FOUND", "message": "任务不存在", "details": {} }` |
| 命名 | 路径用复数资源名 + kebab-case；JSON 字段用 camelCase |
| 幂等 | POST 创建用 `Idempotency-Key` 头（可选，先记录不做） |

## 二、状态码约定

| 码 | 什么时候用 |
|---|---|
| 200 | 查询/更新成功 |
| 201 | 创建成功（响应带 `Location`） |
| 204 | 删除成功、无响应体 |
| 400 | 请求格式错（JSON 解析失败） |
| 401 | 未登录 / token 过期 |
| 403 | 已登录但无权限（访问别人的任务） |
| 404 | 资源不存在 |
| 409 | 冲突（邮箱已被注册） |
| 422 | 校验失败（字段格式不对） |
| 500 | 服务端异常，不要暴露堆栈 |

## 四、接口细节（示例：创建任务）

```http
POST /api/v1/tasks
Authorization: Bearer <token>
Content-Type: application/json

{ "title": "写周报", "dueAt": "2026-11-20T10:00:00Z", "tags": ["work"] }
```

**成功 201**
```json
{ "id": "t_123", "title": "写周报", "done": false, "dueAt": "2026-11-20T10:00:00Z", "tags": ["work"], "createdAt": "2026-11-15T08:00:00Z" }
```

**失败**
| 码 | code | 场景 |
|---|---|---|
| 401 | UNAUTHORIZED | 没带 token |
| 422 | TITLE_REQUIRED | `title` 为空或超 200 字 |
| 422 | TITLE_TOO_LONG | 超过 200 字 |

> 复制这个结构，把总表里每个接口补一段。

## 五、自检

- [ ] 每个接口都能对应到一条用户故事
- [ ] 路径是资源型的，没有动词（没有 `/getTasks`、`/createTask`）
- [ ] 错误格式、分页格式在所有接口一致
- [ ] 写清了"访问别人的任务返回什么"（403 还是 404？为什么）
- [ ] 前端需要的数据，一个接口能拿到（没有"列表页要请求 3 次才能渲染"）
- [ ] 能说出 PATCH 和 PUT 的区别，以及你为什么用 PATCH
