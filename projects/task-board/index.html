    D30：值与类型

    先预测每个表达式的结果，再打开浏览器开发者工具（F12）的 Console，逐条输入并按 Enter。Console 显示的字符串结果会带引号。

    表达式验证

    1 == '1'              // true：== 会进行类型转换，把 '1' 转成数字 1
1 === '1'             // false：=== 不转换类型，number 和 string 不同
typeof null           // "object"：JavaScript 保留至今的历史行为
null == undefined     // true：这是 == 的特殊规则
NaN === NaN           // false：NaN 与任何值比较都不相等，包括它自己
'5' - 1               // 4：减法会把字符串 '5' 转成数字
[] + {}               // "[object Object]"：[] 转成空字符串，对象转成字符串后再拼接

    判断是否为 NaN 时使用 Number.isNaN(value)。日常比较优先用 ===，只有明确需要宽松比较时才考虑 ==。

    模板字符串

    const learnerName = '小明';
const lessonDay = 30;
`你好，${learnerName}！今天学习 D${lessonDay}。`

    反引号包裹模板字符串，${...} 可以插入变量或表达式，也支持换行。

    可选链与空值合并

    const learner = { profile: { name: '小明' } };
learner?.profile?.name ?? '匿名';  // "小明"

const guest = null;
guest?.profile?.name ?? '匿名';    // "匿名"

    ?. 遇到 null 或 undefined 时停止继续读取属性；?? 只在左侧为 null 或 undefined 时使用右侧默认值。

    0 || 10   // 10：|| 把 0 当作假值
0 ?? 10   // 0：?? 保留 0
'' || '默认'  // "默认"
'' ?? '默认'  // ""

    练习完成标准：能解释 7 个表达式的结果，说明 ?? 与 || 的差异，并知道比较时为什么优先使用 ===。

    D31：函数与闭包

    先预测结果，再在浏览器开发者工具（F12）的 Console 运行。函数每调用一次，都会创建自己的局部变量；返回的内层函数可以继续访问创建它时所在的词法作用域。

    实验 1：两个独立的计数器

    function counter() {
    let n = 0;
    return () => ++n;
}

var c1 = counter();
var c2 = counter();
[c1(), c1(), c2()]  // [1, 2, 1]

    c1 和 c2 分别保留了各自调用 counter() 时创建的作用域，因此它们操作的是不同的 n。闭包不是把某个值“记住”，而是让函数仍能通过作用域链访问外层变量。

    实验 2：只执行一次的 once

    function once(fn) {
    let called = false;
    let result;
    return (...args) => {
        if (!called) {
            called = true;
            result = fn(...args);
        }
        return result;
    };
}

var onceCalls = 0;
var greetOnce = once(name => {
    onceCalls += 1;
    return `你好，${name}`;
});
[greetOnce('小明'), greetOnce('小红'), onceCalls]
// ['你好，小明', '你好，小明', 1]

    这个版本只调用原函数一次，并把第一次的返回值交给后续调用；called 和 result 由返回的函数通过闭包继续访问。

    实验 3：缓存结果的 memoize

    function memoize(fn) {
    const cache = new Map();
    return value => {
        if (cache.has(value)) return cache.get(value);
        const result = fn(value);
        cache.set(value, result);
        return result;
    };
}

var squareCalls = 0;
var square = memoize(n => {
    squareCalls += 1;
    return n * n;
});
[square(5), square(5), squareCalls]  // [25, 25, 1]

    这里的 memoize 示例针对单个参数：第一次计算后把参数和结果放进 Map，同一参数再次传入时直接取缓存。

    练习完成标准：能解释计数器结果和两个闭包保存的状态，并能说明 once 与 memoize 分别缓存了什么。

      D35：作用域与 this

      普通函数的 this 看调用方式；箭头函数没有自己的 this，会从定义位置外层作用域取得。先预测每段结果，再分别在 Console 运行。

      1. 普通函数

    return this === globalThis;

      普通函数的 this 由调用形式决定；若函数是严格模式，独立调用时不会自动指向全局对象。

      2. 对象方法

    name: '小明',
    getName() {

      3. 箭头函数

    name: '外层对象',
    makeGetter() {
        return () => this.name;
    }
};
var getterD35 = ownerD35.makeGetter();
getterD35.call({ name: 'call 传入的对象' });  // '外层对象'

      箭头函数的 this 在创建时从 makeGetter 的外层作用域取得，之后用 call 也不能改掉它。

      4. call 和 apply

      function greetD35(greeting, punctuation) {
    return `${greeting}，${this.name}${punctuation}`;
}

      call 接收逐个参数；apply 把参数放在数组里。两者都会在调用时指定普通函数的 this。

      5. 事件回调

      尚未点击

      使用普通函数监听事件时，this 指向注册监听器的元素，也就是 event.currentTarget。箭头函数不会自动把 this 设为按钮。

        D37：DOM 事件与传播

        点击普通子按钮，观察捕获阶段和冒泡阶段的日志；也可以点文字中的“点我”，对比 event.target 与 event.currentTarget。

        父元素 点这里：preventDefault 阻止链接跳转

        这是链接默认跳转的目标位置。

          传播顺序

          • 捕获：从外层父元素向目标元素走。
          • 目标：事件到达实际触发事件的元素。
          • 冒泡：从目标元素向外层父元素返回。

          普通子按钮的顺序是“父捕获 → 子目标 → 父冒泡”。日志同时写入页面和 Console，并记录传播阶段。

          target 与 currentTarget

          event.target 是最初触发事件的元素；event.currentTarget 是当前正在执行监听器的元素。点按钮里的文字时，目标可能是内部 span，而按钮监听器的 currentTarget 是按钮。

          preventDefault 与 stopPropagation

          • 点链接：preventDefault() 阻止浏览器跳转，但父元素仍会收到事件并记录冒泡。
          • 点 stopPropagation 按钮：捕获监听器先运行，按钮监听器调用 stopPropagation() 后，父元素的冒泡监听器不会运行。

          它们作用不同：一个取消浏览器默认动作，一个停止事件继续传播。练习标准：能说出捕获与冒泡方向、区分 target/currentTarget，并解释两个方法各自阻止什么。

            D39：Promise

            在本地预览地址或 GitHub Pages 上运行本节练习。两个 JSON 文件是同源静态接口；不要用 file:// 打开，否则浏览器会限制 fetch。

            delay(ms)：把定时器包装成 Promise

            function delayD39(ms) {
    return new Promise(resolve => {
        setTimeout(resolve, ms);
    });
}
delayD39(300).then(() => console.log('300 毫秒后完成'));

            then 链与微任务顺序

            console.log('同步 1');
Promise.resolve('A')
    .then(value => {
        console.log('then 1', value);
        return 'B';
    })
    .then(value => console.log('then 2', value));
console.log('同步 2');
// 顺序：同步 1 → 同步 2 → then 1 A → then 2 B

            then 回调进入微任务队列；当前同步代码先执行完，再按队列顺序执行 Promise 回调。后一个 then 接收前一个回调返回的值。

            Promise.race 做超时竞速

            race 采用最先完成的结果。下面较慢的请求需要 900ms，超时 Promise 在 300ms 拒绝，所以输出超时错误。

            const request = delayD39(900).then(() => '请求完成');
const timeout = new Promise((resolve, reject) => {
    setTimeout(() => reject(new Error('请求超时')), 300);
});
Promise.race([request, timeout]).catch(error => console.log(error.message));
