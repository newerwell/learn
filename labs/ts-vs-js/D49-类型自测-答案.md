# D49 类型自测 · 答案与解释

> 先做 `labs/ts-vs-js/ts/07-quiz.ts`，再来看这里。每题分「答案 / 为什么 / 自检断言」。
> 自检断言：把它粘贴进 `07-quiz.ts` 对应位置，`pnpm run check` 通过说明你的理解正确。

## Q1 字面量推断

**答案**：`q1a` 是 `string`；`q1b` 是 `'hi'`。

**为什么**：`const` 声明不可变，TS 直接把它收窄成字面量类型；`let` 可能被重新赋值，只能退到 `string`。

**自检**
```ts
const q1aCheck: string = q1a;
const q1bCheck: 'hi' = q1b;
```

## Q2 `as const`

**答案**：`q2` 是 `readonly ['admin', 'user']`；`q2[0]` 是 `'admin'`；`q2.push('x')` 编译报错（readonly 数组没有 push）。

**为什么**：`as const` 做三件事——字面量收窄、数组变 `readonly` 元组、对象属性变 `readonly`。它是"让常量保留精确信息"的标准手段，`type Role = (typeof ROLES)[number]` 就靠它。

**自检**
```ts
const q2Check: readonly ['admin', 'user'] = q2;
type Q2First = (typeof q2)[0];
const q2FirstCheck: Q2First = 'admin';
```

## Q3 interface 重复声明

**答案**：能通过。两个 `interface Q3` 会被**合并**，最终要求同时有 `a` 和 `b`。

**为什么**：这是 interface 独有的"声明合并"。`type` 不行——同名 `type` 会直接报"重复标识符"。选 interface 还是 type，关键看你要不要这个能力。

**自检**
```ts
const q3Check: { a: number; b: string } = q3;
```

## Q4 可选参数

**答案**：`a` 的类型是 `number | undefined`；`q4()` 返回 `0`，`q4(5)` 返回 `5`。

**为什么**：`?` 就是"可能不传"，等价于 `number | undefined`。用 `??` 兜底比 `||` 好——`||` 会把 `0` 也当假值。

**自检**
```ts
const q4Check: number = q4();
```

## Q5 `Omit`

**答案**：`{ title: string; dueAt?: string; tags: string[] }`。

**为什么**：`Omit<T, K>` 从 T 里删掉 K 里的键。注意 `dueAt` 的可选性被**保留**了——工具类型只改键集合，不改修饰符。

**自检**
```ts
const q5Check: { title: string; dueAt?: string; tags: string[] } = q5;
```

## Q6 `keyof` + `Record`

**答案**：`Q6Keys = 'id' | 'title' | 'done' | 'dueAt' | 'tags'`。

**为什么**：`keyof` 取所有键名组成联合；`Record<K, V>` 要求每个 K 都有值。两者组合常用于"字段标签映射"，你 `d47-derived-types.ts` 里的 `Record<TaskField, string>` 就是这个模式。

Q6 里的 `[key: string]: number` 是字符串索引签名：对象可有任意字符串键，但对应值必须是 `number`；因此 `count: number` 合法，`label: string` 报错。

**自检**
```ts
const q6Check: Record<'id' | 'title' | 'done' | 'dueAt' | 'tags', string> = q6;
```

## Q7 `typeof` 与条件类型

**答案**：`Q7` 是**类型** `{ a: number; b: string }`（值 `q7Value` 的推断类型）；`Q7A` 是 `'其他'`，`Q7B` 是 `'文本'`。

**为什么**：同一个 `typeof` 关键字，在表达式里返回字符串（运行时）；在类型位置是"取某个值的类型"。条件类型 `T extends string ? A : B` 会根据类型关系选择结果：数字 `a` 走 `'其他'` 分支，字符串 `b` 走 `'文本'` 分支。

**自检**
```ts
const q7Check: { a: number; b: string } = q7;
```

## Q8 `unknown` 收窄

**答案**：`'A'`、`'1.00'`、`'other'`。

**为什么**：`typeof` 分支把 `unknown` 收窄成 `string` / `number`，剩下的落到 `return 'other'`。注意 `null` 的 `typeof` 是 `'object'`，所以它没被前两支接住。

**自检**
```ts
const q8Check: string = q8('a');
```

## Q9 判别联合

**答案**：会报错。`x.kind === 'a'` 分支里 `x` 已收窄为 `{ kind: 'a'; a: number }`，访问 `x.b` 报 TS2339。

**为什么**：判别联合 + 字面量 `kind` 是穷尽检查的基础。好处是加了一个新 `kind` 时，`switch` 里漏掉分支会被编译器指出来。

**自检**
```ts
// 取消注释应报错：TS2339 Property 'b' does not exist
// function q9bad(x: Q9) { return x.kind === 'a' ? x.b : x.a; }
```

## Q10 结构化类型

**答案**：能通过（`q10raw` 是变量，多余属性检查不生效）；被注释的 `q10bad` 会报 TS2353。

**为什么**：多余属性检查只在"对象字面量直接赋给目标类型"时触发，它的目的是抓拼写错误，不是禁止额外字段。所以"先存变量再赋值"能绕过——这也说明 TS 的类型是结构契约。

**自检**
```ts
const q10Check: { x: number } = q10;
```
