### D68 ⭐ useMutation：失效与乐观更新

**动手**：
~~~tsx
type TaskPage = {
  items: Task[];
  total: number;
  page: number;
  pageSize: number;
};

const toggle = useMutation({
  mutationFn: (t: Task) => patchTask(t.id, { done: !t.done }),
  onMutate: async (t) => {
    await queryClient.cancelQueries({ queryKey: ['tasks'] });
    const key = ['tasks', { page, q, done }] as const;
    const previous = queryClient.getQueryData<TaskPage>(key);
    queryClient.setQueryData<TaskPage>(key, (old) => {
      if (!old) return old;
      return {
        ...old,
        items: old.items.map((item) =>
          item.id === t.id ? { ...item, done: !t.done } : item
        ),
      };
    });
    return { key, previous };
  },
  onError: (_error, _task, context) => {
    if (context?.previous) {
      queryClient.setQueryData(context.key, context.previous);
    }
  },
  onSettled: () => queryClient.invalidateQueries({ queryKey: ['tasks'] }),
});
~~~

乐观更新要创建新分页对象和新 tasks 数组，不能修改缓存中的 old 或 old.items。请求失败时用 previous 回滚；结束后失效查询并以服务器数据校准。

**判据**
- 勾选立即生效（不等服务器），失败后能回滚
- 能解释 `onMutate` / `onError` / `onSettled` 各自时机
- 知道什么时候**不该**乐观更新（涉及金额、库存这类）

## 六个 React 高频坑（提前知道能省几小时）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| 直接改 state | 页面不更新 | 用 `[...arr]` / `{...obj}` 造新引用 |
| 用 index 当 key | 删中间项后状态错位 | 用稳定 id |
| useEffect 里改 state 做派生 | 渲染两次、循环更新 | 直接在渲染中算 |
| 过度提升状态 | 层层传 props | 就近原则，只有共享才提升 |
| 忘记清理副作用 | 定时器叠加、订阅泄漏 | 返回清理函数 |
| Query 里 key 写错 | 缓存不共享、重复请求 | key 按"资源 + 参数"设计 |
