### D2 管道、查找、环境变量

**30 分钟 摸**
- 管道 `|` 的意思：上一条命令的输出变成下一条的输入
- `$env:PATH`、`$env:PATH -split ';'`、`where.exe node`（找命令实际位置）
- `Get-Process`、`Stop-Process -Name xxx`（别关系统进程）
- PowerShell 里没有 `grep`，对应的是 `Select-String`

**45 分钟 写**
```powershell
# 1. 找本项目里所有含 "pwsh" 的文件行
Get-ChildItem -Recurse -File -Include *.md,*.ps1 | Select-String 'pwsh' | Select-Object Path,LineNumber,Line

# 2. 统计 projects 下文件数量与总大小
Get-ChildItem projects -Recurse -File | Measure-Object -Property Length -Sum

# 3. 按大小排序看前 5 个
Get-ChildItem -Recurse -File | Sort-Object Length -Descending | Select-Object -First 5 Name,Length

# 4. 看清哪些命令是别名（别名指向谁）
Get-Alias | Where-Object { $_.Name -in 'ls','cat','curl','grep' } | Format-Table -AutoSize
```

观察第 4 条：`ls`/`cat` 是别名，但 `curl` 在 7 里指向真正的 `curl.exe`——**用 `curl.exe` 就不会被别名坑**。

**完成判据**
- 能用**一条**管道找出仓库下所有含某关键词的文件并只显示路径
- 能解释 `where.exe node` 输出的每一行是什么
- 知道 `>` 重定向在 PowerShell 里默认写 UTF-16，要写 UTF-8 得用 `| Out-File -Encoding utf8`

### D3 Git 三区与提交

**30 分钟 摸**：working tree（工作区）→ index（暂存区）→ HEAD（版本库）。`git status` 的每一行都在描述这三者的差异。

**45 分钟 写**
```powershell
cd C:\Users\xiaomi\Desktop\learning\fullstack-journey
git status
Set-Content projects\playground\note.txt "v1"
git status                      # 看到 untracked
git add projects\playground\note.txt
git status                      # 看到 changes to be committed
git diff                        # 工作区 vs 暂存区：应该空
git commit -m "w01d3: 第一次手写提交"
git log --oneline --graph
Set-Content projects\playground\note.txt "v2"
git diff                        # 工作区 vs 暂存区：有差异

git add -A; git commit -m "w01d3: 改 v2"
git show --stat HEAD
```

**完成判据**

### D4 分支与冲突

**30 分钟 摸**：分支只是一个指针（ref），不是复制文件。`switch -c` 建分支 = 建指针 + 切 HEAD。

**45 分钟 写**
```powershell
git switch -c feature/w1d4
# 改 README.md 里"当前周"那一行 → 提交
git add -A; git commit -m "w01d4: feature 分支改当前周"
git switch main
# 改同一行成别的内容 → 提交
git add -A; git commit -m "w01d4: main 改当前周"
git merge feature/w1d4          # 冲突
# 打开冲突文件，认 <<<<<<< ======= >>>>>>> 三段标记，手工改成想要的结果
git add -A; git commit -m "w01d4: 解决冲突"
git log --oneline --graph --all
```

再练一次“后悔药”：
```powershell
git reset --hard HEAD~1        # 故意丢一次提交
git reflog                     # 找到刚才的 hash
git reset --hard <那个hash>     # 找回来
```

**完成判据**
- 能读懂冲突标记的三个部分各代表谁
- 能用 reflog 找回一次被 `reset --hard` 丢掉的提交
- 能说出 merge 和 rebase 的差别（rebase 会改写历史，只在本地未推送的分支上用）

### D13 用 node:http 起第一个服务

新建 `server.js`：
```js
const http = require('node:http');
const server = http.createServer((req, res) => {
  console.log(req.method, req.url);
  res.setHeader('Content-Type', 'application/json; charset=utf-8');
  if (req.url === '/api/hello') {
    res.end(JSON.stringify({ msg: '你好，这是我第一个接口' }));
  } else {
    res.statusCode = 404;
    res.end(JSON.stringify({ error: 'Not Found', path: req.url }));
  }
});
server.listen(3000, '127.0.0.1', () => console.log('http://127.0.0.1:3000'));
```
```powershell
node server.js
# 另开一个终端（或浏览器）
curl.exe -i http://127.0.0.1:3000/api/hello
curl.exe -i http://127.0.0.1:3000/nope
```

**完成判据**
- 能解释“端口被占用”（EADDRINUSE）的原因和两种解法（换端口 / 杀进程）
- 能说出一个请求从进来到你的 `createServer` 回调之间发生了什么

## 常见报错对照表（PowerShell 特有）

| 现象 | 原因 | 解法 |
|---|---|---|
| `因为在此系统上禁止运行脚本` | ExecutionPolicy 默认 Restricted | `pwsh -File x.ps1` 一般可跑；或 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| `>` 重定向后文件乱码/变大 | PowerShell `>` 默认写 UTF-16 | 用 `\| Out-File -Encoding utf8` 或 `\| Set-Content -Encoding utf8` |
| `curl: 无法将...识别为 cmdlet` | 5.1 里 `curl` 是 `Invoke-WebRequest` 的别名 | 一律写 `curl.exe` |
| 路径报错 | 带空格未加引号 | `cd "C:\Program Files"` |
| `git` 提示 LF/CRLF | Windows 换行差异 | 无害；本仓库有 `.gitattributes` |
| `pnpm install` 很慢 | 默认源在境外 | `pnpm config set registry https://registry.npmmirror.com` |

## 卡住时的处理顺序

1. 把**报错原文**整段复制到笔记（不要截图，要文字）
2. 先读报错里的文件名和行号——80% 的答案在报错里
3. 再 `Get-Help <命令> -Examples` / 官方文档
4. 都不行再搜索，搜索时带上**语言 + 库名 + 报错关键短语**
5. 超过 45 分钟没解决就记进 `??` 队列，第二天再攻——别在一处耗死
