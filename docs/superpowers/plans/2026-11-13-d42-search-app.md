# D42 Search App Implementation Plan

**Goal:** Build a small public-API search app that demonstrates debouncing, list rendering, four request states, persistent search history, and retryable errors.

**Architecture:** Add a self-contained vanilla HTML/CSS/JS app under the existing Pages source directory and link it from the task board. Use GitHub's public repository search endpoint; keep search state and safe DOM rendering in one small script.

**Tech Stack:** HTML, CSS, JavaScript, Fetch API, AbortController, localStorage.

**Spec:** `notes/W3-W8-任务.md`, D42.

## Global Constraints

- Keep the app inside `projects/task-board/` so the existing Pages source publishes it.
- Use no API key or third-party dependency.
- Render API data as text, not HTML.

## Review Focus

- Empty API results must render an empty state.
- Network, timeout, HTTP, and rate-limit errors must offer an in-page retry.
- A newer query must not be overwritten by an older response.
- Invalid or unavailable localStorage must not break searching.
- Repository links must remain HTTPS links to GitHub.

## Approaches

- Movie or weather API: may require a key or introduce another provider's limits.
- GitHub repository search: public and key-free; unauthenticated search is rate-limited, so show a recoverable message. **Chosen** for easy setup and useful result metadata.

## Files

- Create `projects/task-board/search-app/index.html`, `styles.css`, and `app.js`.
- Modify `projects/task-board/index.html` to add a D42 section and app link.

## Steps

1. Create the semantic responsive app shell and four request-state placeholders.
2. Implement debounced search, request cancellation/timeout, safe result rendering, retry, and localStorage history.
3. Link the app from the task board, inspect the final diff, and run static checks.
